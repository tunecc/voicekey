## Requirements

### Requirement: 会话事件提示音

应用必须在录音会话的四个关键事件（录音开始、进入识别处理、处理完成（结果就绪）、识别失败（含转写超时与出错））遵循用户选择的音效方案与总开关发出提示音：简洁方案仅开始与处理发声（纯双音，见下述场景），完成与失败不发声；自定义方案四事件均按逐事件选择发声。取消录音时不得播放任何提示音。

#### Scenario: 录音开始发声

- **WHEN** 用户通过热键或托盘触发一次正式录音开始
- **THEN** 播放「录音开始」事件在当前音效方案下使用的提示音

#### Scenario: 进入识别处理发声

- **WHEN** 录音结束、应用进入识别处理状态
- **THEN** 播放「处理」事件在当前音效方案下使用的提示音

#### Scenario: 处理完成发声

- **WHEN** 识别结果就绪（单候选直接注入，或多候选面板呈现）
- **THEN** 播放「完成」事件在当前音效方案下使用的提示音

#### Scenario: 识别失败发声

- **WHEN** 识别失败、出错或转写超时
- **THEN** 播放「失败」事件在当前音效方案下使用的提示音

#### Scenario: 简洁方案开始与处理按固定映射发声

- **WHEN** 音效方案为简洁，录音开始或进入识别处理
- **THEN** 录音开始播轻巧"叮"声、进入识别处理播轻弹"啵"声；macOS 上播放系统提示音 Tink 与 Pop（与 cometix-dictation 一致），Windows 上播放内置近似音；系统音不可用时回退内置近似音

#### Scenario: 简洁方案完成与失败不发声

- **WHEN** 音效方案为简洁，识别完成或识别失败
- **THEN** 不播放提示音（纯双音极简风格）

#### Scenario: 自定义方案逐事件发声

- **WHEN** 音效方案为自定义
- **THEN** 各事件播放用户为该事件选中的音效，四个事件的发声互不干扰

#### Scenario: 取消录音不发声

- **WHEN** 用户在识别完成前取消录音会话
- **THEN** 不播放任何提示音

### Requirement: 提示音设置

音频设置页必须提供提示音设置组：音效方案选择控件（简洁、自定义两选一，默认自定义），以及提示音总开关（默认开启）。自定义方案下必须提供录音开始、处理、完成、失败四个事件各自独立的音效选择控件，音效必须从内置音效集合中选择；简洁方案下必须以只读方式展示发声事件（录音开始、进入识别处理）的固定音效映射，并明确标注完成与失败不发声，且不得提供逐事件音效选择控件。音效方案、总开关与逐事件选择的任一设置变更必须即时生效并持久化。

#### Scenario: 关闭总开关后全静音

- **WHEN** 提示音总开关处于关闭状态
- **THEN** 无论音效方案为何，四个事件均不播放提示音，其余功能行为不变

#### Scenario: 方案切换即时生效

- **WHEN** 用户在简洁与自定义之间切换音效方案
- **THEN** 后续会话事件立即按新方案的规则发声，无需重启应用

#### Scenario: 简洁方案隐藏逐事件选择

- **WHEN** 音效方案为简洁
- **THEN** 设置页只读展示开始与处理的固定音效映射，标注完成与失败不发声，不展示逐事件音效选择控件

#### Scenario: 自定义方案恢复逐事件选择

- **WHEN** 音效方案切回自定义
- **THEN** 四个事件的音效选择控件恢复显示，且各事件保持此前已保存的选择

#### Scenario: 逐事件选择独立生效

- **WHEN** 音效方案为自定义，用户为某一个事件选择不同的音效
- **THEN** 该事件改播新选音效，其余事件保持各自原有音效

#### Scenario: 设置持久化

- **WHEN** 用户修改音效方案、总开关或逐事件音效选择后重启应用
- **THEN** 音效方案、总开关状态与各事件的音效选择与重启前一致

#### Scenario: 缺省字段兜底

- **WHEN** 现有配置文件缺少音效方案或提示音相关字段
- **THEN** 音效方案按默认值（自定义）生效，总开关按默认值（开启）生效，各事件使用默认音效，不产生错误

### Requirement: 音效试听

音频设置页中简洁方案的发声事件行与自定义方案的每个事件行旁必须提供试听按钮；点击试听必须立即播放该事件在当前音效方案与当前平台下实际使用的音效（简洁方案在 macOS 播系统音、Windows 播内置近似音；自定义方案播当前选中的音效），不发声的事件不提供试听，且试听不得修改任何设置。

#### Scenario: 点击试听立即播放

- **WHEN** 用户点击某事件的试听按钮
- **THEN** 立即播放该事件在当前音效方案与平台下的实际音效，且不改变音效方案或任何事件的设置

### Requirement: 内置音效与跨平台一致

自定义方案的音效选择必须使用应用内置自带的开源授权（允许再分发）音效集合，不得依赖操作系统音效目录，macOS 与 Windows 的可选音效集合一致；简洁方案在 macOS 直接使用系统提示音 Tink/Pop（运行时引用、不随应用分发），Windows 使用内置开源授权近似音兜底，两平台简洁方案的发声语义一致（仅开始与处理发声）。

#### Scenario: 无系统音效目录依赖

- **WHEN** 在任一受支持平台（macOS 或 Windows）上打开自定义方案的音效选择
- **THEN** 可选音效来自应用内置集合，且两平台的可选集合一致

#### Scenario: 简洁方案平台差异兜底

- **WHEN** 简洁方案在 Windows 上触发录音开始或进入识别处理
- **THEN** 使用内置近似音发声，发声事件与 macOS 一致（完成与失败同样不发声）

### Requirement: 主流程不受影响

提示音的播放不得改变录音、识别与结果注入的行为与时序；提示音资源缺失或播放失败时必须静默跳过，不得向用户报错或中断会话。

#### Scenario: 播放失败静默降级

- **WHEN** 某提示音资源缺失或播放失败
- **THEN** 该次提示音被跳过，应用不显示错误，录音与识别流程按无提示音时的方式继续

#### Scenario: 行为与时序不变

- **WHEN** 提示音功能处于开启状态并在各事件播放
- **THEN** 录音、识别、结果注入的行为与关闭提示音时一致
