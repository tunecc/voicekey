# Proposal

## 问题描述

开始录音时的提示音（叮咚声）前后，系统输出音量出现「减小 → 放大 → 再减小」的往返变化，听感混乱。用户期望的包络是：正常音量播放开始音 → 播完后音量减小并保持到录音结束，不要来回跳动。

## 根因分析

音量往返来自两个功能叠加后的时序组合（`app/src-tauri/src/controller.rs`）：

1. `cbeb69d` 引入「录音时调整音量」：`arm()`（按下热键预开麦）时立即压低系统输出音量，防止预开麦窗口内扬声器声音进入麦克风 —— **第 1 次减小**。
2. `da38c63` 引入「先播音、后压音量」：为让开始音不被压低的音量吞掉，确认开始录音时先 `restore_volume()` 还原音量再播开始音 —— **第 2 次（放大）**；开始音播完后经 `Msg::LowerVolume` 再压低 —— **第 3 次（减小）**。

按下 → 确认的每一次开始录音都会完整经历这三次音量变化；结束录音时再还原一次。

## 修复目标

- 开始音始终以用户当前正常音量播放，播完后系统音量**单次**压低到设置值，录音期间保持，结束时还原。
- 移除 `arm()` 预压低与确认时的还原（含 `arm()` 开麦失败、`disarm()` 取消预开麦两处配对还原），消除「减小 → 放大 → 再减小」的往返。
- 不改变：压低/还原的设置项语义（`录音时调整音量`、目标值 0–100）、录音主体期间的防漏音能力、开始音与压低音量的先后顺序（先播音、后压音量）。

## 已知取舍

移除 `arm()` 预压低后，从按下热键到开始音播完的预开麦窗口内，若正在外放媒体，会以原始音量进入录音头部（恢复 `cbeb69d` 引入之前的行为）。录音主体期间（占绝对时长）的防漏音不受影响。

## 验证与自动化说明

音量包络是 macOS 系统级听感行为，`Ctl` 与 Tauri `AppHandle` 深耦合，仓库无 headless 应用测试设施，无法在 CI 中自动复现「三次音量变化」。按 hotfix 预设记录手工复现证据：

- 设置「录音时调整音量」目标为非 100 值（默认 15），外放任意媒体
- 长按热键开始录音：旧实现音量依次出现 压低（按下）→ 还原（确认+开始音）→ 再压低（开始音播完），共 3 次变化（用户报告与此一致）
- 修复后：按下与确认阶段音量无变化，开始音以正常音量播完，仅播完后压低 1 次，结束时还原

自动化部分：`RecordingVolume` 状态机（crates/core）已有压低/还原语义单测保持通过；本次修复仅删减 controller 中的调用点，不新增逻辑。
