# Proposal

## Why

「录音时降低音量」功能合入后，「处理」提示音仍在录音结束瞬间播放——此时系统输出音量处于压低状态（约为原音量的 30%），提示音明显偏小、难以听清。用户（简洁方案使用者）期望该提示音在识别完成、音量恢复后再响，作为「结果就绪」的可闻信号。

## What Changes

- 「处理」提示音的触发时机从「录音结束、进入识别处理」改为「识别结果就绪、系统输出音量恢复后」：
  - 移除录音结束路径（进入识别处理时）的 `SoundEvent::Processing` 播放
  - 在全部结果就绪路径（单候选注入、多候选面板）改为播放「处理」提示音，随后按音效时长间隔播放「完成」提示音
  - 等待方式：记录录音结束时刻，结果就绪时若距结束不足恢复窗口（约 0.45s 上限）则补足等待；不新增平台音量 API
- 识别失败路径不播放「处理」提示音，仅播放「失败」提示音（时机不变）
- delta spec 修改 audio-feedback 的「会话事件提示音」需求；事件配置模型（四事件、逐事件选择、持久化）不变

### Modified Capabilities

- `audio-feedback`: 「会话事件提示音」需求——「处理」事件触发时机改为识别完成（结果就绪）且系统输出音量恢复后；识别失败不再伴随「处理」提示音

## Impact

- `app/src-tauri/src/controller.rs`：提示音触发点调整（新增录音结束时刻记录与恢复窗口等待）
- `docs/openspec/specs/audio-feedback/spec.md`：归档时按 delta 合并
- 用户可感行为：简洁方案下提示音序列从「开始音→结束即小声啵」变为「开始音→结果就绪后全音量啵」；自定义方案下结果就绪时会连续听到「处理音+完成音」两声（用户已确认接受）
