# Spec Delta

## MODIFIED Requirements

### Requirement: 会话事件提示音

应用必须在录音会话的关键事件（录音开始、识别结果就绪、识别失败（含转写超时与出错））遵循用户选择的音效方案与总开关发出提示音：「处理」事件的提示音必须（MUST）在识别结果就绪、系统输出音量恢复后播放，随后同批播放「完成」事件提示音（两音按时长间隔，不重叠）；录音结束、进入识别处理状态时不播放任何提示音；识别失败时不播放「处理」提示音，仅播放「失败」提示音。简洁方案仅开始与结果就绪时发声（纯双音，见下述场景），失败不发声；自定义方案下各事件按逐事件选择发声，选择「无」的事件不发声，其余事件互不干扰。取消录音时不得播放任何提示音。提示音的等待与播放必须（MUST）异步执行，不得阻塞或延迟识别与结果注入。

#### Scenario: 录音开始发声

- **WHEN** 用户通过热键或托盘触发一次正式录音开始
- **THEN** 播放「录音开始」事件在当前音效方案下使用的提示音

#### Scenario: 进入识别处理发声

- **WHEN** 录音结束、应用进入识别处理状态（结果尚未就绪）
- **THEN** 不播放任何提示音；「处理」事件提示音改于识别结果就绪、系统输出音量恢复后播放

#### Scenario: 处理完成发声

- **WHEN** 识别结果就绪（单候选直接注入，或多候选面板呈现）且系统输出音量已恢复
- **THEN** 先播放「处理」事件在当前音效方案下使用的提示音，随后按时长间隔播放「完成」事件提示音（该事件配置为发声时）

#### Scenario: 识别失败发声

- **WHEN** 识别失败、出错或转写超时
- **THEN** 仅播放「失败」事件在当前音效方案下使用的提示音，不播放「处理」事件提示音

#### Scenario: 简洁方案开始与处理按固定映射发声

- **WHEN** 音效方案为简洁，录音开始或识别结果就绪
- **THEN** 录音开始播轻巧"叮"声、结果就绪时播轻弹"啵"声；macOS 上播放系统提示音 Tink 与 Pop（与 cometix-dictation 一致），Windows 上播放内置近似音；系统音不可用时回退内置近似音

#### Scenario: 简洁方案完成与失败不发声

- **WHEN** 音效方案为简洁，识别完成或识别失败
- **THEN** 不播放「完成」与「失败」事件提示音（纯双音极简风格；结果就绪时仍播「处理」提示音）

#### Scenario: 自定义方案逐事件发声

- **WHEN** 音效方案为自定义
- **THEN** 各事件播放用户为该事件选中的音效；选择为「无」的事件不发声，四个事件的发声互不干扰

#### Scenario: 取消录音不发声

- **WHEN** 用户在识别完成前取消录音会话
- **THEN** 不播放任何提示音
