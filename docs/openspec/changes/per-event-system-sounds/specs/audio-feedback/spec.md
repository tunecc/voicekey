# Spec Delta

## MODIFIED Requirements

### Requirement: 会话事件提示音

应用必须在录音会话的关键事件（录音开始、识别结果就绪、识别失败（含转写超时与出错））遵循总开关与逐事件音效选择发出提示音：四个事件各自使用用户从 macOS 系统铃声中选择的音效（或「不发声」），默认值——录音开始=Tink、识别处理=Pop、识别完成=不发声、识别失败=Basso。「处理」事件的提示音必须（MUST）在录音结束进入识别处理时播放，且必须（MUST）等系统输出音量恢复后再播（恢复窗口机制）；「完成」事件默认不发声（识别很快，完成不另发音效）；取消录音时不得播放任何提示音。提示音的等待与播放必须（MUST）异步执行，不得阻塞或延迟识别与结果注入。

#### Scenario: 录音开始发声

- **WHEN** 用户通过热键或托盘触发一次正式录音开始
- **THEN** 按录音开始事件的当前选择播放提示音（默认 Tink）

#### Scenario: 进入识别处理发声

- **WHEN** 录音结束、应用进入识别处理状态
- **THEN** 播放处理事件当前选择的提示音（默认 Pop），且在系统输出音量恢复后播出

#### Scenario: 处理完成发声

- **WHEN** 识别结果就绪（单候选直接注入，或多候选面板呈现）
- **THEN** 不播放「完成」事件提示音（默认不发声；完成信号由进入识别时的处理提示音承担）

#### Scenario: 识别失败发声

- **WHEN** 识别失败、出错或转写超时
- **THEN** 仅播放失败事件当前选择的提示音（默认 Basso），不播放处理事件提示音；录音刚结束时须等系统输出音量恢复后再播

#### Scenario: 简洁方案开始与处理按固定映射发声

- **WHEN** 四个事件均保持默认选择
- **THEN** 录音开始播 Tink、结果就绪前进入识别时播 Pop、识别失败播 Basso（macOS 系统铃声；Windows 按同名内置近似音兜底），完成保持不发声

#### Scenario: 简洁方案完成与失败不发声

- **WHEN** 识别完成
- **THEN** 不播放「完成」事件提示音（识别很快，完成信号由进入识别时的处理提示音承担）。识别失败的发声规则已改为逐事件可选（默认 Basso），不再适用本场景

#### Scenario: 自定义方案逐事件发声

- **WHEN** 用户为四个事件分别选择不同的 macOS 系统铃声或「不发声」
- **THEN** 各事件按各自当前选择发声或不发声，互不干扰

#### Scenario: 取消录音不发声

- **WHEN** 用户在识别完成前取消录音会话
- **THEN** 不播放任何提示音

### Requirement: 提示音设置

音频设置页必须提供提示音设置组：提示音总开关（默认开启），以及四个事件（录音开始、识别处理、识别完成、识别失败）各自的系统铃声选择控件——每个控件必须在「不发声」与 macOS 系统铃声集合之间选择，默认值分别为 Tink/Pop/不发声/Basso；发声事件行提供试听按钮且试听即所得（播放所选系统铃声），「不发声」事件不提供试听。每行副标题只描述该事件对应的会话时刻。设置变更必须即时生效并持久化。历史配置中的池内音效 id（不属于系统铃声集合）必须回退为该事件默认值，不得产生错误。

#### Scenario: 关闭总开关后全静音

- **WHEN** 提示音总开关处于关闭状态
- **THEN** 所有事件均不播放提示音，其余功能行为不变

#### Scenario: 方案切换即时生效

- **WHEN** 读取历史配置中的音效方案字段
- **THEN** 音效方案概念已移除，设置页不再展示该控件，各事件恒按各自的系统铃声选择发声

#### Scenario: 简洁方案隐藏逐事件选择

- **WHEN** 查看提示音设置组
- **THEN** 四个事件行各自展示系统铃声选择控件（「不发声」+ macOS 系统铃声集合，默认 Tink/Pop/不发声/Basso），每行副标题只描述该事件对应的会话时刻，不展示音效方案选择控件

#### Scenario: 自定义方案恢复逐事件选择

- **WHEN** 查看逐事件选择控件的可选项
- **THEN** 选项池为 macOS 系统铃声集合（含「不发声」），不包含历史池内 WAV 音效

#### Scenario: 逐事件选择独立生效

- **WHEN** 用户为某一个事件改选不同的系统铃声或「不发声」
- **THEN** 该事件按新选择发声或不发声，其余事件保持各自原有选择

#### Scenario: 逐事件「无」持久化

- **WHEN** 用户将某事件选择为「不发声」后重启应用
- **THEN** 该事件的选择仍为「不发声」，不得回退为默认音效，其余事件的选择与重启前一致

#### Scenario: 设置持久化

- **WHEN** 用户修改总开关或任一事件的系统铃声选择后重启应用
- **THEN** 总开关状态与各事件的选择与重启前一致

#### Scenario: 缺省字段兜底

- **WHEN** 现有配置文件中的事件音效值不属于系统铃声集合（如历史池内 id）
- **THEN** 该事件回退为默认值（Tink/Pop/不发声/Basso），不产生错误

### Requirement: 内置音效与跨平台一致

macOS 上事件提示音直接使用系统铃声（NSSound 运行时引用、不随应用分发）；Windows 无对应系统音，事件选中的音效若存在同名内置近似音（tink.wav/pop.wav/error.wav）则以其发声，否则该事件在 Windows 上静音——此为已知平台限制；默认值组合（Tink/Pop/不发声/Basso）在两平台均可发声（失败在 Windows 播内置「警示」近似音）。

#### Scenario: 无系统音效目录依赖

- **WHEN** 在 macOS 上触发任一事件提示音
- **THEN** 播放选中的系统铃声，运行时引用系统音目录，不随应用分发

#### Scenario: 简洁方案平台差异兜底

- **WHEN** Windows 上以默认值组合触发录音开始、识别结果就绪或识别失败
- **THEN** 分别播放内置近似音 tink.wav/pop.wav/error.wav（完成不发声）；未提供同名近似音的选择在 Windows 静音
